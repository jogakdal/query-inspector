# 국제화 (i18n) 정책

LLM 기반 스킬의 i18n은 전통적 "문자열 리소스 번들"이 아니라 **출력 언어 지시 + 언어 중립 식별자**로 구성한다. LLM이 번역 주체이므로, 우리는 *무엇을 어떤 언어로 낼지*와 *무엇을 번역하지 말지*만 규정한다.

## 3층 모델

| 층 | 예 | 정책 |
|----|----|------|
| **출력층** - 사용자가 보는 것 | 리포트, 터미널 요약, **첫 실행 범위 확인 질문/배치 진행 안내 등 사용자에게 하는 모든 발화** | **다국어.** `report.language`로 렌더. LLM이 해당 언어로 생성 |
| **식별자층** - 언어 중립 | 휴리스틱 ID(`n_plus_one`), 신뢰도 라벨(`EXACT`/`INFERRED`/`AMBIGUOUS`), 심각도 토큰(`critical`/`warn`/`info`), 설정 키, 어댑터명, 방언 토큰 | **번역 금지.** 어느 언어에서도 동일. 리포트에선 표시명만 지역화 |
| **지침층** - Claude가 읽는 문서 | `SKILL.md`, `references/**` | LLM이 어느 언어든 이해하므로 그대로 둔다(사용자에게 직접 노출되지 않음). `description`만 다국어 트리거 키워드를 병기 |

## 출력 언어 결정 규칙

1. `--lang <code>` 인자가 있으면 그것.
2. 없으면 `report.language` 설정. `auto`(기본)면 **사용자 대화 언어(locale)** 를 따른다.
3. 감지 불가 시 `en`으로 폴백.
4. 리포트 헤더에 사용 언어를 표기(예: `언어: ko` / `Language: en`).

지원 코드(초기): `ko`, `en`. 확장: `ja`, `zh`, ... (LLM이 생성하므로 코드 추가만으로 가능, 사전 항목은 아래 확장).

## 지역화 대상 / 비대상

- ✅ **지역화:** 리포트의 섹션 제목/근거 문장/수정 제안 설명/커버리지/한계 문구/강등 사유/검증 방법 안내.
- ❌ **비지역화(그대로):** 휴리스틱 ID, 신뢰도/심각도 라벨 상수, SQL 텍스트, 설정 키, 파일 경로, 어댑터/방언 이름, 코드 식별자.

> 원칙: **기계가 파싱하거나 설정이 참조하는 토큰은 언어 중립**, **사람이 읽고 이해하는 산문은 지역화**.

## 리포트 라벨 사전 (표시명)

식별자층 토큰을 출력층에서 어떻게 표기할지의 참고 사전. LLM이 자연스럽게 번역하되 일관성을 위해 권장어를 둔다.

| 토큰(ID/상수) | ko | en |
|---|---|---|
| 섹션: summary | 요약 | Summary |
| 섹션: details | 상세 | Details |
| 섹션: coverage | 커버리지 & 한계 | Coverage & Limits |
| field: source | 원천 | Source |
| field: inferred_sql | 추론 SQL | Inferred SQL |
| field: rationale | 근거 | Rationale |
| field: suggestion | 제안 | Suggestion |
| field: verification | 검증 방법 | How to verify |
| severity `critical` | 심각 | Critical |
| severity `warn` | 경고 | Warning |
| severity `info` | 정보 | Info |
| confidence `EXACT` | (그대로) EXACT | EXACT |
| `n_plus_one` 표시명 | N+1 조회 | N+1 queries |
| `select_star` 표시명 | 전체 컬럼 조회(SELECT *) | SELECT * / over-fetching |
| `non_sargable_predicate` | 인덱스 무력화 조건 | Non-SARGable predicate |
| `leading_wildcard_like` | 선행 와일드카드 LIKE | Leading-wildcard LIKE |
| `unbounded_result` | 제한 없는 대량 조회 | Unbounded result set |
| `missing_index` 표시명 | 인덱스 누락 | Missing index |
| `dialect_pipe_concat` | 방언 불일치 문법 | Dialect mismatch syntax |
| `string_substitution` | 문자열 치환 인젝션 | String-substitution injection |
| `order_by_filesort` | 인덱스 없는 정렬 | Filesort (no index) |
| `derived_table_filter` | 파생 테이블 밖 필터 | Derived-table filter (no pushdown) |
| `implicit_type_cast` | 암시적 타입 변환 | Implicit type cast |
| `cartesian_join` | 카티전 곱 / 조인 조건 누락 | Cartesian / cross join |
| `large_in_clause` | 대량 IN 바인딩 | Large IN clause |
| `deep_pagination` | 깊은 OFFSET 페이징 | Deep offset pagination |
| `distinct_abuse` | 불필요한 DISTINCT | Unnecessary DISTINCT |
| `correlated_subquery` | 상관 서브쿼리 | Correlated subquery |
| `or_predicate_index` | OR 조건 인덱스 저해 | OR predicate index breakage |
| `count_large` | 대량 COUNT / 전량 집계 | Large COUNT / full aggregation |
| `transaction_lock_scope` | 트랜잭션/락 범위 과다 | Excessive transaction/lock scope |

> 신뢰도 라벨(`EXACT`/`INFERRED`/`AMBIGUOUS`)은 **어느 언어에서도 원문 유지**를 권장(교차 참조/grep 안정성). 필요하면 괄호로 현지어 병기.

## 스크립트 메시지

`scripts/*`의 출력은 대부분 **Claude가 소비하는 중간 산출물**이라 사용자에게 직접 보이지 않는다. 따라서:

- 스크립트 출력은 대부분 Claude가 소비하는 중간 산출물이라 언어에 민감하지 않다(한국어 허용).
- 사용자에게 직접 보이는 메시지가 생기면 `report.language`/`--lang`를 존중한다.
- **특히 `collect_diff.py`의 범위 요약/`--count-only` 규모 출력은 Stage 0에서 사용자에게 그대로 제시**된다. 스크립트 출력 자체는 한국어로 고정돼 있으므로, **Claude가 이를 `report.language`로 재서술**해 전달한다(스크립트는 수치/유형/경로 같은 언어중립 데이터를 담고, 사용자 표시 문장은 LLM이 렌더). `report.language=en/ja` 사용자에게 이 부분만 한국어로 튀지 않게 한다.

## 사용자 대면 문서 (정적 문서 / 인라인 help)

GitHub 등에서 사람이 읽는 정적 문서와, 스킬이 출력하는 인라인 도움말은 처리가 다르다.

- **정적 문서(`README`/`MANUAL`)** - **영어 정본 + 언어별 파일**(`README.md`/`MANUAL.md`=영어, `README.ko.md`/`MANUAL.ko.md`=한국어). 상단에 `English | 한국어` 스위처를 둔다.
  - **동기화는 "내용(정보)"의 동기화이지 문장 복제가 아니다.** 각 언어를 **그 언어의 자연스러운 원문**으로 쓴다 - 한국어본이 영어의 축자 번역(번역체)처럼 읽히면 안 된다. 사용자 대면 문서를 바꿀 때 양 언어를 함께 갱신한다.
- **인라인 help(`assets/help.md`)** - **출력층**이다. 파일은 영어(정본)로 두되, 스킬이 `--help`를 낼 때 `report.language`(대화 언어)로 **렌더**한다(옵션/플래그/경로 등 식별자는 그대로, 설명 산문만 지역화). 언어별 help 파일을 따로 두지 않는다.
- **지침층(`SKILL.md`/`references/**`)** - 위 3층 모델대로 그대로 둔다(LLM이 어느 언어든 이해; 사용자에게 직접 노출되지 않음).

## 스킬이 제어할 수 없는 것

- **Claude Code 하네스가 내는 시스템 메시지**(예: 작업 디렉토리 밖 파일 읽기 권한 확인 프롬프트)는 스킬 밖이라 `report.language`로 제어할 수 없다. Claude Code UI/환경 설정을 따른다.

## i18n 점검 항목

- [ ] `description`에 다국어 트리거 키워드 병기(KO/EN).
- [ ] 리포트 출력 다국어 검증을 `claude plugin eval`에 언어별 케이스로 추가(ko/en 최소).
- [ ] 라벨 사전(위) 완비 + 신규 휴리스틱 추가 시 사전 동기화.
- [ ] 사용자 대면 문서(README/MANUAL) 변경 시 영어 정본 + 한국어본을 함께 갱신(각 언어 자연스러운 원문 유지).
