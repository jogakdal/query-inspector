# 자가 진단 모드 (`--self-diagnose-internal`, 내부 전용/undocumented)

이 문서는 `--self-diagnose-internal` 플래그가 주어졌을 때만 활성화되는 **내부 개발용 자가 진단 절차**다. 사용자 대면 문서(help/README/MANUAL)에는 노출하지 않는다(undocumented). 목적은 스킬을 반복 수정/검증하는 동안 **스킬 자신의 실행 환경/지침 품질/버그/개선점**을, 스킬을 실행하는 주체(AI)가 관찰해 로컬 리포트로 남기는 것이다.

## 활성 조건과 기본 원칙

- `--self-diagnose-internal`이 인자에 있을 때만 수행한다. 없으면 이 문서 전체를 무시한다.
- **정상 실행을 최우선으로 유지한다.** 평소의 튜닝/인벤토리 파이프라인을 그대로 전부 수행하고 정규 리포트도 평소대로 생성한다. 진단은 그 위에 얹는 **추가 산출물**이며, 정규 분석의 범위/판정/출력을 바꾸지 않는다.
- **로컬 전용.** 진단 결과는 로컬 파일로만 기록한다. 어떤 온라인 전송도 하지 않는다(네트워크 호출/업로드/외부 API 금지). 수집 정보에 자격증명/비밀값을 담지 않는다(호스트/DB명까지만, 비번 마스킹 - 정규 리포트 규칙과 동일).
- **관찰자 자세.** "잘 동작했다"가 아니라 **문제를 적극적으로 찾는다.** 애매했던 판단, 조용히 넘어간 강등, 지침이 불명확해 임의로 해석한 지점을 솔직히 기록한다. 확신이 없는 것은 확신이 없다고 쓴다.

## 관찰 항목 (실행 내내 수집)

파이프라인 각 단계를 지나는 동안 아래를 메모해 둔다. 실행이 끝난 뒤 진단 리포트로 정리한다.

### 1. 실행 환경
- OS / 사용한 파이썬 명령(python3/python/py)과 그 선택 과정 / git 저장소 여부.
- 설정 파일(`.query-inspector.yml`) 존재 여부와 파싱 결과(없어서 example 기본값을 썼는지).
- 각 스크립트 호출의 종료코드와 비정상 여부(collect_diff/db_guard/run_explain/version_check/blame_author).
- Tier 강등이 있었는가. 있었다면 어느 Tier에서 왜(스키마 없음/`--db` 미제공/의존성 부재/접속 실패 등).
- 선택적 의존성 가용성(PyYAML, pymysql/psycopg, mysql/psql CLI).

### 2. 지침/동작 이슈 (스킬 자체 품질)
- 지침(SKILL.md/pipeline-common/어댑터/heuristics)이 **모호하거나 모순**돼 해석이 갈린 지점 - 어느 문서 어느 대목인지 적시한다.
- 서로 다른 지침이 충돌한 경우(예: 범위 규칙 vs 어댑터 지시).
- 어댑터가 **다루지 못한 코드 패턴**(라우팅은 됐으나 규칙에 없던 구문, 또는 라우팅 자체 실패).
- 문서(SKILL/MANUAL/어댑터)가 기술한 동작과 **실제 수행 결과의 불일치**.
- 지침을 따르는 데 필요한 정보가 없어 **추측으로 메운** 지점.

### 3. 분석 자기평가 (이번 실행 결과의 신뢰성)
- 추출/재구성에서 **자신 없던 쿼리**(왜 애매했는지).
- 오탐(실제로는 문제가 아닌데 지적) 또는 미탐(놓쳤을 가능성) 의심 항목.
- 신뢰도 라벨(`EXACT`/`INFERRED`/`AMBIGUOUS`) 부여가 애매했던 경우.
- 방언 판정의 근거가 약했던 경우.

### 4. 버그/예외
- 스크립트 에러/크래시/스택트레이스(**원문 그대로 인용**, 단 경로의 사용자명 등 민감정보 주의).
- 경로/인코딩/플랫폼 관련 문제.
- 예상과 다른 출력(스크립트 반환이 문서화된 형식과 다른 경우 등).

### 5. 개선 제안
- 위 관찰에서 도출한 구체적 수정안을 **우선순위(높음/중간/낮음)**로 적는다.
- 각 제안에 **대상 파일/지침 지점**과 근거를 명시한다(예: "`references/adapters/python-django.md`에 X 구문 규칙 추가", "`pipeline-common` Stage 0.5 방언 근거 우선순위 모호").

## 진단 리포트 생성/저장

정규 리포트를 낸 **직후**, 별도 진단 리포트를 생성한다.

- 저장 위치: `<report.dir>/diagnostics/<timestamp>.md`(기본 `docs/query-inspector/diagnostics/`). 정규 리포트와 **다른 폴더**에 두어 섞이지 않게 한다.
- `diagnostics/`에 `.gitignore`(`*`)가 없으면 생성한다(진단 결과는 로컬 전용, 커밋 방지).
- 터미널에는 "진단 리포트도 생성했습니다: <경로>" 한 줄과 상위 개선 제안 2~3개만 요약한다(정규 요약 뒤에).

### 리포트 구조

```markdown
# query-inspector 자가 진단 리포트

- 스킬: <tuning-report|inventory-report>  버전: <version_check --local 결과>
- 실행 인자: <원래 호출 인자 전부>
- 대상 범위: <증분/전체 + 파일/쿼리 수>
- 일시: <timestamp>
- 모드: self-diagnose-internal (로컬 전용, 미전송)

## 1. 실행 환경
...

## 2. 지침/동작 이슈
...

## 3. 분석 자기평가
...

## 4. 버그/예외
...

## 5. 개선 제안 (우선순위순)
- [높음] <대상 파일/지점> - <제안> (근거: ...)
- [중간] ...
- [낮음] ...

## 요약
<이번 실행에서 가장 주목할 1~3가지>
```

- 관찰된 것이 없는 범주는 "특이사항 없음"으로 명시한다(빈 섹션 금지 - 안 본 것인지 없는 것인지 구분).
- 정규 리포트의 내용을 복제하지 않는다. 진단은 **스킬 자체에 대한 메타 관찰**이지 쿼리 분석 결과가 아니다.
