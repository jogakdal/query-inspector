# 리포트 문체 규약 (생성 문서 강제)

이 플러그인이 생성하는 **리포트 산문**(튜닝 리포트, 쿼리 인벤토리, 자가 진단 리포트의 제목/근거/제안/안내 문장)에 적용하는 문체 규약이다. 실행하는 AI나 장비의 성향과 무관하게 **항상 이 규약을 따라** 리포트를 작성해, 산출 문서의 품질을 균일하게 유지한다.

> 이 문서는 범용 문서 문체 지침(`writing-text-style`)에서 **리포트 작성에 필요한 부분만 발췌·고정한 스냅샷**이다. 원 지침의 갱신을 추적하지 않는다. 분석 판정 규칙(`heuristics.md` 등)과 별개로, "리포트를 어떻게 쓰는가"만 규정한다.

## 적용 범위

- **한국어 리포트(`report.language`가 ko, 또는 auto에서 사용자 대화 언어가 한국어)**: 아래 전 규칙을 **강제**한다.
- **영문 리포트**: 과장/의인화/구어 자제 등 기본 원칙만 적용하고, 영어권에서 일반적/관용적인 표현(명료한 대조, 전개용 표현)은 유지한다. 한국어 전용 규칙(명사구 제목 강제 등)은 영문에 적용하지 않는다.
- 식별자/코드/SQL은 어느 언어에서도 원문 유지(아래 "표기 층위").

## 1. 한국어 리포트 문체 (강제)

### 제목
- **섹션 제목은 명사구**(서술형/의문형 금지): "쿼리가 하는 일" -> "쿼리 분석 범위", "인덱스를 추가해야 한다" -> "인덱스 추가 제안". 한정이 필요하면 줄표로: "오버레이 - 핵심이자 약점".

### 동사/표현
- **모호한 동사 -> 협의 한자어**(의미역을 좁힌다): 본다 -> 점검/분석한다, 잡는다 -> 검출한다, 갈린다 -> 구분된다, 준다 -> 제시한다, 나온다 -> 도출된다, 다룬다 -> 한정/정의한다, 바꾼다 -> 변환/대체한다. 판정법: 그 동사에 서로 다른 목적어를 끼워 모두 자연스러우면 협의어로 분리한다.
- **의인화/물리 은유 자제**: "N+1이 사는 곳", "쿼리가 흐른다", "값이 튄다", "조용히 ~한다". 주어를 사람/사물로 바꿔 자연스러우면 은유다. 중립 동사로 쓴다.
- **구어체 환언 금지**: "보는 전부" -> "검출 범위", "반토막" -> "절반 수준", "손도 못 댄다" -> "관여하지 않는다".
- **말에서 줄인 표현 풀어 쓰기**:
  - **구어 동사/직역 동사 -> 동작 동사**: 돌리다 -> 실행한다, 쓰다(사용) -> 사용한다, 켜다/끄다 -> 활성화/비활성화한다, 깔다 -> 설치한다, 띄우다 -> 실행/표시한다, 당기다(pull) -> 수신/반영한다, 밀다(push) -> 전송/게시한다, 죽이다(kill) -> 종료한다. 판정법: 동사를 물리 동작(바퀴를 돌리다, 줄을 당기다)으로 읽을 수 있으면 대상이다.
  - **"있다/없다"로 서술한 지원 여부 -> "지원한다/하지 않는다"**: "인덱스 커버 확인은 없다" -> "인덱스 커버를 확인하지 않는다". 실재하는 대상의 부재("해당 컬럼이 인덱스에 없다")는 그대로 둔다.
  - **명사형 상태 서술 금지**: "기본 꺼짐이다" -> "기본값은 비활성이다". 상태는 값을 주어로 삼거나 동사로 적는다(표 셀/괄호 부기는 예외).
  - **지시 대명사 -> 명사 반복**: "여기서 실행한다" -> "그 디렉토리에서 실행한다"(가리키는 명사로). "이 설정"/"해당 컬럼"처럼 지시 관형사+명사는 그대로 둔다.
  - **주어/목적어 생략 금지**: 문장마다 대상을 다시 적는다(행위자가 독자/작성자로 분명한 절차 서술은 예외).
- **기호/수단을 주어로 한 "이다" 등식 금지**(표기 규칙은 뜻을 주어로): "🔴은 critical이다" -> "critical은 🔴로 표시한다". 가리키는 대상(뜻/행위)을 주어로 두고 관계를 동사로 쓴다. 기호에서 뜻을 찾는 범례는 문장이 아니라 표로 만든다.
- **번역투 제거**:
  - 2인칭 "당신"(you의 직역)은 "사용 중인"/"해당"/"이 ~"로.
  - 추상 원인 주어 + 결과 타동사(영어 능동문 직역): 원인은 부사어("~로"/"~에 따라"), 결과는 자동사로. "이 설정이 응답을 늘린다" -> "이 설정으로 응답이 늘어난다".
  - 추상명사 + "있다"로 현상 서술: "영향이 있을 수 있다" -> "현상이 나타날 수 있다".
  - 피동 남용 자제. 자동사("달라지다/늘어나다/드러나다")를 우선한다.
- **과장/단정/위협 자제**: "가장 ~한", "완벽한/강력한/유일한", "...만 하면 끝", "지금 안 하면 위험". 사실을 중립적으로 적는다. (우선순위를 나타내는 "최우선" 등 사실 표현은 유지.)

### 어미
- 리포트 본문은 **평서체**(`~한다`/`~이다`)로 일관한다. 사용자에게 직접 하는 안내/확인 문장만 합니다체로 분리하고, 한 문서에서 두 체를 섞지 않는다.
- **독자에게 하는 요청/지시**: 직접 명령("~하세요"/"~해라"/"~하십시오")을 쓰지 않는다. **보조용언을 붙인 "~해 주세요", "~해 주십시오"도 명령형이라 같다**(허용되는 것은 보조용언 "-해 주-" 자체이지 명령 종결이 아니다). 평서체 문서는 "~한다"로 서술하고, 수행하지 않으면 동작하지 않는 **필수 조치는 "~해야 한다"**로 적는다("`--db` 프로파일을 먼저 지정해야 한다"). 번호를 매긴 절차 단계는 "~합니다"로, 안내 문서에서 독자에게 따로 하는 요청은 "~해 주시기 바랍니다"로 적는다. (블로그/홍보 글은 "~해 주세요"를 허용.)

## 2. 공통 (한/영 모두)

### 표기 층위
- **식별자/API/enum/필드명은 영문 원문 그대로**(번역 금지): `SUCCESS`를 "성공"으로 적지 않는다. 휴리스틱 ID(`missing_index`), 신뢰도 라벨(`EXACT`/`INFERRED`/`AMBIGUOUS`), 심각도 토큰(`critical`/`warn`/`info`), SQL 텍스트, 파일 경로, 컬럼/테이블명은 언어 중립으로 유지한다.
- 정밀도 없는 격식체(`상기`/`익일`/`요망`)는 "위"/"다음 날"/"요청한다"로.

### non-ASCII 구두점
- 타이포그래피 특수문자 대신 ASCII를 쓴다: em dash `—` -> `-`, 가운뎃점 `·` -> `/`(문맥에 따라 `,`), 화살표 `→` -> `->`, 말줄임표 `…` -> `...`, 곱셈 `×` -> `x`, 스마트 따옴표 -> 곧은 따옴표.
- **예외(유지)**: 본문 언어 문자(한글 등), 코드/SQL/데이터에 원래 있던 문자, 심각도/상태 이모지(`🔴🟡⚪`/`✅⚠️❌❓`).

### 구조/가독성
- **짧은 문단**(1~3문장). 긴 설명은 쪼갠다. 개행을 의미 단위로 쓴다.
- **축약 우선**: 근거/제안은 핵심만 남긴다. 리스트/표로 나눌 수 있으면 문단보다 리스트.

### 정확성 표기
- 추정을 실측처럼 쓰지 않는다. 신뢰도 라벨(`EXACT`/`INFERRED`/`AMBIGUOUS`)과 검증 수준(정적 추론/컴파일 확인/EXPLAIN 실측)을 각 항목에 부기한다(리포트 템플릿 필드와 연계).

### 서명 금지
- 리포트에 가시적 서명("AI로 작성" 등)/자동 푸터/비가시 표식(제로폭 문자 등)을 넣지 않는다.

## 점검 (리포트 출력 전)
- [ ] (한국어) 섹션 제목이 명사구인가. 모호한 동사/의인화/구어/과장/번역투/기호 등식이 없는가. 어미가 평서체로 일관되는가.
- [ ] (한국어) 구어 동사(돌린다/켠다/깐다/당긴다/민다), "있다/없다" 지원 여부, 명사형 상태("꺼짐이다"), 단독 지시 대명사를 풀어 적었는가. 직접 명령("~하세요") 대신 "~한다"/필수는 "~해야 한다"인가.
- [ ] 식별자/enum/SQL/경로가 영문 원문인가. non-ASCII 구두점을 ASCII로 바꿨는가(이모지 예외).
- [ ] 문단이 짧고 개행이 호흡을 주는가. 신뢰도/검증 수준을 부기했는가. 서명/비가시 표식이 없는가.
